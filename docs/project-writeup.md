# ShiftMind — Project write-up

## One line
ShiftMind transforms scattered industrial shift records into structured operational intelligence, so the
next shift knows what happened, what went wrong and what needs attention.

## Architecture

```
React dashboard  ->  FastAPI  ->  parser  ->  records (SQL)  ->  anomaly rules
                                                  |                    |
                                          summary / handover  <--------+
                                                  |
                                       Ask ShiftMind (retrieval + computed stats)
                                                  |
                                   optional LLM wording (numeric grounding guard)
```

- **Parser** (`services/parser.py`): alias-based header mapping, unit conversion, shift and date
  normalisation, `Key: value` block parsing for PDFs and notes. Output rows carry `source_ref`
  (file + row/line) for traceability.
- **Anomaly engine** (`services/anomaly.py`): pure function over a record and the machine's history.
  Rules cover data integrity, production vs target, downtime, quality, maintenance, and history-based
  checks (z-score, material per unit, repeat failures). Thresholds are in one dict.
- **Summary / handover** (`services/summary.py`): facts first, then text. Actions are generated by
  rules from flags, each with reason and source record; persisted so supervisors can tick them off.
- **Q&A** (`services/qa.py`): deterministic filter extraction, ranked retrieval, Python-computed totals,
  numbered sources. LLM only phrases the answer from the retrieved records.
- **LLM guard** (`services/llm.py`): output is rejected if it contains any number absent from the
  supplied facts; on any failure the rule-based text is used.

## Key decisions
| Decision | Reason |
| --- | --- |
| Rules for anomalies, not an LLM | Auditable, reproducible, no hallucinated figures |
| Reject unreadable rows | Silent guessing in a manufacturing log is worse than a visible gap |
| Works offline without a key | Testable, demoable anywhere, no vendor lock-in |
| Re-run analysis after each upload | History-based rules depend on neighbouring records; data volumes are small |
| SQLite dev / PostgreSQL deploy | One SQLAlchemy code path, zero-setup local run |

## Results on the synthetic dataset
119 records parsed from 4 files in 4 formats. Planted issues found: M-102 repeat overheating
(critical), M-103 impossible 900-minute downtime, M-104 night reject spike, M-105 missing evening report.

## Limitations and next steps
OCR for scanned/handwritten pages; authentication and roles; per-machine thresholds; embeddings for
vague questions; PDF export of the handover; CAPA and batch-record links for GMP environments
(pharma/chemical), audit trail with e-signatures.
